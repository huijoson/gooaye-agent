白話摘要 (Plain Summary)

讓 AI 助理能在不增加常態 Token 開銷（待機 < 50 Tokens）的前提下，精準檢索 689 集股癌觀念並以主委風格提供務實的投資決策與風險心態拷問。

專案擁有 540+ 小時、689 集完整的股癌逐字稿與結構化觀念筆記。若直接做成 Always-on 的重型 Persona Agent 或將資料庫常駐在對話 Prompt，會導致每輪對話消耗數千 Tokens，且容易在歷史搜尋中混入未清洗的業配廣告。本架構採用 Antigravity 漸進式 Skill 體系，配合兩階段階梯檢索與雙模態分流，達到高精確度與極致 Token 節省。

核心架構建議： 建立專案專屬 Skill (.agents/skills/gooaye/SKILL.md)。「查歷史觀點」使用客觀引述（標記集數與逐字稿），「問決策心態」切換為主委語氣（部位控制、期望值、停損紀律）。

改造前後對比 (Before & After)

改造前：無結構掛載或全量 Prompt 注入

flowchart TD
    User["使用者提問"] --> Prompt["全量注入逐字稿 / 始終啟用重型 Persona"]
    Prompt --> Bloat["Token 暴增 每輪超過 3000 Tokens"]
    Prompt --> Noise["混入贊助商廣告與未過濾口語雜音"]

Observed 若未經結構化分層，689 集逐字稿（約 40MB）無法直接放入上下文，粗暴檢索容易引述到廣告業配詞（如銀座白石、NordVPN）。

改造後：漸進式載入與雙模態路由

flowchart TD
    User["使用者提問"] --> Router{"是否涉及股癌話題？"}
    Router -->|否| Standby["日常開發對話 待機僅約 30 tokens"]
    Router -->|是| Skill["動態載入 Gooaye Skill"]
    Skill --> Mode{"意圖分流 Dual-Mode"}
    Mode -->|歷史觀點查詢| Stage1["階梯檢索: _index.md 與 episodes/"]
    Stage1 --> Quote["客觀條列集數、日期、逐字稿引述"]
    Mode -->|投資心態求助| Roaster["主委靈魂拷問: 部位與期望值與停損紀律"]

Decided 平時近乎 0 成本，觸發時精準單點讀取 1~3 篇結構化筆記（每次約 800~1,500 Tokens），既省額度又免受廣告污染。

架構技術與白話翻譯 (Architecture Techniques)

漸進式揭露 (Progressive Disclosure)

白話：「菜單只寫菜名，點了才把整本食譜拿出來」。平時只載入 30 Tokens 的 Skill 摘要，點名才讀取完整規則。

兩階段階梯檢索 (Two-Stage Progressive Search)

白話：「先看書本目錄，再翻那一頁，不要整棟圖書館搬進腦袋」。先比對 _index.md，再讀單篇 3KB 筆記。

雙模態路由 (Dual-Mode Routing)

白話：「查法條時像法官嚴謹，談心態時像兄弟直白開罵」。事實與心態求助分開處理，避免事實被誇飾污染。

風險與開放決策 (Risk & Open Decisions)

最高風險 (Top Risk)： 使用者搜尋冷門或口語同義詞時（如「主委聊過賣飛嗎」），若未命中結構化章節標題，可能需退回全逐字稿 grep，增加單次查詢耗時。
待確認項目 (Open Decision)： 目前核心架構決策已全數關閉（Closed）。後續可視使用習慣決定是否將專案 Skill 複製至個人全域 ~/.gemini/skills/。

界限、所有權與非目標 (Boundary & Non-Goals)

模組所有權 (Ownership)

由 .agents/skills/gooaye/ 擁有檢索意圖識別、Markdown 筆記索引解析、主委 Persona 提示詞封裝之所有權。

系統邊界 (System Seam)

Skill 僅作為 LLM 提示指引與檢索規範，不直接修改底層 gooaye-youtube-notes/ 任何資料檔案。

明確非目標 (Non-Goals)

  • 不提供保證獲利或具體買賣點位建議：恪守主委「獨立思考、自負盈虧」之核心理念。
  • 不自建外部向量資料庫或嵌入微服務：避免引入額外 Python/Rust 相依套件與運維負擔。
  • 不修改現有逐字稿批次管線：不破壞既有 episode_synthesizer.py 與 heading_quality_engine.py 結構。

介面合約 (Interface Contract)

操作 (Operation) 呼叫者 輸入 (Inputs) 輸出 (Outputs) 不變條件 (Invariants) & 限制
Skill Discovery Antigravity Engine 工作區掃描 Name, Description (~30 tokens) 待機時不得載入正文指令。

  • SKILL.md → 依賴 Antigravity 內建檔案檢索工具 (grep_search, view_file)。

禁止的依賴方向 (Forbidden)

  • 禁止 SKILL.md 逆向寫入或修改 episodes/ 檔案。
  • 禁止 將整包 689 集逐字稿在對話起始時預載入 Context。

遷移與驗收計畫 (Migration & Verification)

  1. 第一階段 (Phase 1)：建立 .agents/skills/gooaye/SKILL.md，填入完整的 YAML 宣告、雙模態指令與兩階段檢索 SOP。
  2. 第二階段 (Phase 2)：進行「歷史查證」實測（以 EP690 Google COT 與 ASIC 為例），確認引述與 Markdown 格式精確。
  3. 第三階段 (Phase 3)：進行「心態健檢」實測（以抱過一座山回吐 30% 為例），確認主委語氣到位且 Token 消耗符合預期。
回滾機制 (Rollback)： 若不需要此 Skill，只需刪除 .agents/skills/gooaye/ 目錄，系統即刻回到原始通用 Agent 狀態，無任何副作用。
