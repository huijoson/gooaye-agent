# 系統規格書：Gooaye (股癌) 智能代理技能、漸進式知識庫與跨環境安裝器

## 問題陳述 (Problem Statement)

AI 程式開發與推理助理的使用者需要可靠地查詢《Gooaye 股癌》高達 689 集（540+ 小時）的龐大市場觀點、歷史評述與投資決策思維模型。然而面臨以下核心痛點：
1. 將數百小時的原始逐字稿直接載入 AI Agent 的活躍上下文視窗，會導致嚴重的 Token 膨脹、高延遲、推理品質退化與高昂成本。
2. Podcast 原始逐字稿夾雜大量贊助業配廣告、口語填充詞與標點斷句雜音，容易導致 LLM 產生幻覺或捏造不精準的引述。
3. 使用者存在兩種截然不同的互動需求：一種是客觀嚴謹、具備精確集數與時間脈絡的事實查證；另一種則是以謝孟恭標誌性直白口吻，針對部位管理與認知偏差進行投資心態壓力測試與健檢。
4. 開發者與使用者缺乏一套統一且零摩擦的安裝機制，難以將 Gooaye 技能軟連結（Symlink）或分發至全域環境與其他獨立的專案工作區。

## 解決方案 (Solution)

建立一套符合漸進式按需揭露（Progressive Disclosure）的 Token 高效知識庫與 Agent 技能架構，並搭配自動化跨環境安裝工具：
1. **漸進式揭露技能 (Progressive Skill)**：待機時僅在系統提示中佔用極小元數據開銷（~30 tokens），僅在使用者提出相關問題時動態按需啟用。
2. **階梯式兩階段檢索 (Two-Stage Progressive Retrieval)**：第一階段優先查詢結構化全集索引鎖定 1–3 集目標集數；第二階段僅讀取已去除業配廣告且錨定真實逐字稿引述的章節筆記，避免無謂掃描數百萬字全文。
3. **雙模態運作協定 (Dual-Mode Protocol)**：自動識別使用者意圖並分流為：
   - **歷史觀點查證模式 (Archive Query Mode)**：客觀中立，提供精確集數編號、發布日期與可點擊之 Markdown 筆記連結與真實引述。
   - **主委心態健檢模式 (Mindset Roasting Mode)**：切換謝孟恭直白幽默口吻，以大白話嚴格拷問部位大小、進場理由、停損紀律與期望值。
4. **通用安裝與分發工具 (Universal Installer)**：提供單一指令的自動化腳本，支援全域使用者設定檔 Symlink 連結、指定專案工作區部署、實體複製模式，並提供第三方 AI 工具（如 Claude Code、Cursor、Windsurf）之配置指引。

## 使用者故事 (User Stories)

1. 作為一位研究半導體趨勢的投資者，我想要查詢主委在過去集數中對 ASIC 與 GPU 架構演進的看法，以便於精準對照多年的觀點轉折並取得原始集數引述。
2. 作為一位面臨嚴重帳面虧損的交易者，我想要向主委尋求投資心態健檢，以便於以直白嘴砲的風格被拷問部位大小與停損紀律，避免抱過一座山回吐。
3. 作為一位 AI Agent 使用者，我想要本技能在待機時消耗極低的 Token，以便於在日常編程與通用任務中保持低成本與快速響應。
4. 作為一位擁有多個專案工作區的工程師，我想要透過單一指令將技能全域安裝至本機設定中，以便於在電腦上的任何專案目錄都能隨時向 Agent 調用股癌知識庫。
5. 作為一位特定專案的負責人，我想要將技能配置至指定目標專案的 `.agents/skills` 目錄，以便於隨 Git 版本控制與團隊成員共享。
6. 作為一位詢問特定集數（例如 EP690）的使用者，我想要立即取得該集清洗後的結構化章節與兩條關鍵引述，以便於無需聆聽整整一小時音檔即可掌握核心內容。
7. 作為一位研究員，我想要所有章節筆記自動過濾贊助業配與開頭宣傳詞，以便於引言內容百分之百專注於實質市場與觀念討論。
8. 作為一位品質工程師，我想要章節標題嚴格遵守 9 大品質檢驗閘門（杜絕口語殘句、泛稱詞與摘要抄襲），以便於索引標題精準反映討論主軸。
9. 作為一位無網路連線環境下的開發者，我想要所有筆記檢索與確定性標題修復演算法完全在本地離線運行，以便於系統在無外部依賴時依然穩健運作。
10. 作為其他 AI 工具（如 Claude Code、Cursor、Windsurf）的使用者，我想要標準 Markdown 格式的技能定義與設定指南，以便於無縫導入至其他代理工具。
11. 作為接收投資諮詢的 Agent，我想要嚴格禁止報明牌、預測絕對點位或做出獲利保證，以便於互動完全合規、安全且聚焦於觀念與風險教育。
12. 作為提出模糊投資問題的使用者，我想要 Agent 能自動判斷我的語境意圖並切換對應模式，以便於無需手動下達複雜指令即可獲得適當風格的回覆。
13. 作為維護資料管道的工程師，我想要一個包含體檢（`doctor`）與品質審計（`audit`）的統一命令列工具，以便於隨時驗證全集 689 份筆記的數據完整性。

## 實作決策 (Implementation Decisions)

### 1. 漸進式按需技能架構
- **定義與觸發**：採用標準 YAML frontmatter 封裝名稱與簡明描述（~30 tokens），平時處於待機狀態，僅在使用者提問符合特徵時由模型按需加載完整指令。
- **意圖分流路由**：技能指令定義清晰的雙模態分流規則：
  - 個股、產業、特定集數、歷史事件等名詞查詢自動路由至**歷史觀點查證模式**。
  - 套牢、追高 FOMO、停損猶豫、槓桿恐慌等情緒諮詢自動路由至**主委心態健檢模式**。

### 2. 階梯式兩階段檢索架構
- **第一階段（索引定位）**：優先掃描輕量化全集總大綱索引或針對筆記標題進行關鍵字篩選，精準鎖定最相關的 1–3 集。
- **第二階段（結構化筆記讀取）**：僅加載命中的單集結構化筆記（每集約 800–1,500 tokens），獲取已清洗廣告之章節標題與雙真實引述。
- **第三階段（深層驗證接縫，可選）**：僅在需要回溯完整段落語境時，定點查閱本地完整逐字稿。

### 3. 通用安裝器腳本
- **介面與行為**：
  - 實作符合 POSIX 標準之 Shell 腳本，支援 `--global`（預設）、`--target <路徑>` 與 `--copy` 參數。
  - 將技能目錄軟連結至全域設定目錄（`~/.gemini/config/skills/gooaye` 與相容目錄）。
  - 支援冪等性重複執行，安全覆蓋與更新既有符號連結。

### 4. 數據合成管道與標題品質引擎
- **品質閘門 9 大瑕疵分類**：嚴格偵測格式異常（`FORMAT`）、泛稱詞（`GENERIC_TERMS`）、轉折前綴（`TRANSITION_PREFIX`）、對話殘句（`CONVERSATIONAL_FRAGMENT`）、機械黏合（`MACHINE_GLUE`）、摘要洩漏（`SUMMARY_LEAKAGE`）、弱接地（`WEAK_GROUNDING`）、英文字詞截斷（`BROKEN_LATIN`）與語法未閉合（`UNBALANCED_SYNTAX`）。
- **多層級解析器降級接縫**：優先讀取驗證快取，未命中或驗證失敗時依序降級至多層級純 Python 確定性修復演算法或本地 LLM 結構化生成。

## 測試決策 (Testing Decisions)

### 良好測試準則
- 測試必須驗證系統的**外部可觀察行為與介面合約**，而非內部實作細節。
- 檢索測試需驗證能否針對特定主題準確輸出對應集數、日期、引述與筆記路徑。
- 安裝器測試需驗證檔案系統符號連結建立、路徑解析正確性與冪等性執行狀態碼。
- 品質引擎測試需驗證瑕疵輸入能被正確分類診斷，並由確定性修復演算法產出合規標題。

### 受測核心接縫 (Testing Seams)
- **最高層接縫 1：技能安裝器 CLI**：執行安裝腳本並驗證目的目錄、符號連結有效性與執行權限。
- **最高層接縫 2：標題品質與解析引擎**：輸入含 9 大瑕疵之測試字串，驗證診斷報告及修復結果之合規性。
- **最高層接縫 3：筆記合成調度器與渲染器**：對測試逐字稿執行單集與批次合成，驗證輸出 Markdown 結構、YAML metadata 與引述格式。

### 既有測試參考 (Prior Art)
- 代碼庫既有測試套件涵蓋領域模型、特徵抽取器、標題品質引擎、解析器、渲染器與合成調度器，共計 32 項單元測試全數通過。

## 範疇之外 (Out of Scope)

- 即時股市報價 API 串接或即時交易行情推送。
- 個性化個股買賣推薦、絕對目標價預測或代客操作等投資顧問業務。
- 部署外部雲端向量資料庫（系統嚴格基於本地輕量級階梯式檢索與確定性索引）。
- 技能即時運行時的語音轉文字（STT）處理（逐字稿已預先處理完畢）。

- 系統架構與領域規範完整記錄於 `CONTEXT.md`、`README.md` 與 `docs/adr/0001-progressive-gooaye-skill.md`。
